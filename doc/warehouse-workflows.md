# 仓库库存控制与退货、调拨

本次补齐盘点冻结与复盘、按用途退供应商、批次冻结、跨仓调拨和客户退货。所有实物变化经过 `StockOp`，业务单据、数量和流水在同一事务内提交。

## 盘点

1. 草稿仅定义范围，不能录入实盘数。开始盘点后冻结所选商品、库位和批次，方可打印实盘单。
   发现漏盘项时，先通过补录入口加入商品、库位、批次并冻结，再实际点数并在明细中录入；补录建行不能同时提交实盘数量。
2. 同范围另一张盘点不能同时开始。该范围有已录入但尚未完成的拣货时，须先结束拣货。
3. 冻结拦截上架、下架、移库、拣货、调拨接收和其他调整。零差异完成即释放；有差异的盘点在其调整单过账后释放。
4. `POST /cyclecount/{id}/resolve/cancel` 取消并释放；`resolve/recount` 作废未过账调整并创建关联复盘，冻结连续转交，不重复扣减。均需 `reason`。已过账盘点只能开始新一轮复盘，不能撤销既有流水。

`cycle_count_edit` 管理取消与复盘；原 `cycle_count_execute` 仍可执行盘点；调整继续使用既有审批权限。

## 退供应商

DN 增加 `stock_source`、`supplier_id`、`purpose_reason`。普通销售使用 `standard`；破损退供使用 `damaged`；普通退供可选择 `standard`、`damaged`、`return`。

三类预占分别保存在 `dn_stock`、`damaged_dn_stock`、`return_dn_stock`。破损和退货预占不挤占正常可售库存。拣货必须使用对应库位类型。明确退供用途允许冻结或过期批次；销售仍禁止。短装、取消保持质量属性：正常货退待上架、破损货退破损待上架、退货品回退货库位。

客户退货审批产生的退供 DN 锁定原批次和已检库位，不能自行改量或更换收货方。未拣出的批准库存仍受库位保护。短拣、短装、取消把对应数量恢复到原退货单的待检持有量，重新检验或提出处理意见后才可使用。

## 批次冻结

`GET /goods/{goods_id}/lots/{lot_id}/control` 返回当前状态、版本、范围内库存、未发货单据和变更历史。

`POST` 接收 `status: active|hold`、当前 `revision`、`reason`；旧版本返回 409。冻结影响销售建单可用量、拣货、发货及调拨正常品接收。解除冻结不改变有效期。批次属于公司，变更需要 `inventory_edit` 及该公司全部启用仓库的访问权；单仓员工可查看其范围内影响。

## 跨仓调拨

页面：`/stock-operations/transfers`。创建时选同公司两个启用仓库，明细包含商品、原批次、源标准库位和计划数量。

接口：`GET/POST /transfer/orders`、`GET /transfer/orders/{id}`、`POST /transfer/orders/{id}/{ship|receive|loss|cancel}`。

- 调出：源库位扣减，源仓在途增加。
- 接收：同一调拨行的在途扣减，目标仓库位增加，保留批次；可分次接收至正常、破损或退货库位。
- 差异：未接收量保持在途。确认损失使用 `loss`，需 `adjustment_approve`，记录原因。
- 取消：仅取消未调出余量，保留原计划数量与取消量；已调出部分仍需接收或核销。

读取使用 `transfer_read`，操作使用 `transfer_edit`。创建要求两个仓库均在授权范围；调出、取消、损失在源仓操作，接收在目标仓操作。页面显示在途账龄与逐次操作历史。

## 客户退货

页面：`/stock-operations/returns`。接口：`GET/POST /asn/returns`、`GET /asn/returns/{id}`、`POST /asn/returns/{id}/{receive|cancel|propose}`、`POST /asn/returns/{id}/dispositions/{decision_id}/review`。

1. 关联已发货销售 DN，按商品、实际出库批次限制累计退货授权量。取消只释放未接收授权。
2. 无原单退货必须另外具备 `inventory_edit`，填写异常原因与客户，不允许静默跳过原单校验。
3. 实收只能进入退货库位，产生逐单待检持有量；普通移库、调整和出库不能绕过待检保护。
4. 处理意见支持正常回库、转破损、转维修、报废、退供应商。提出意见需 `asn_edit` 和 `inventory_edit`；另一个具备 `adjustment_approve` 的用户批准或驳回，并记录审核原因。
5. 维修只变更待检库位，仍不能销售；正常回库再次校验批次可发货条件；退供生成关联 DN，后续取消或短拣会回到待检。

## 请求重试与追踪

动作请求必须使用稳定的 8–64 字符 `request_id`。同一单据、同一请求号及相同内容重试返回当前单据，不重复记账；改内容重用请求号返回 409。创建也接受稳定请求号，旧调用方省略时服务端生成；集成方需要自行重试保障时必须提供该值。

列表支持 `page`、`per_page`（1–100）、`keyword`（编号或原因）、`status`。Web 保存失败保留请求号，库存流水可跳转关联单据。详细原因保存在业务事件中；流水 `reason` 沿用原有 30 字符展示限制。

## 升级与旧单据

先备份数据库，再使用项目原有迁移命令 `flask db upgrade` 升级至 `c3f7a1b8d590`。新增两版：`b2e6f0a7c489` 为盘点控制，`c3f7a1b8d590` 为库存池、冻结审计、调拨和退货表。

- 已开始、已录入或已完成的旧盘点标记为 `legacy`，不追溯冻结，不直接用旧差异新过账；通过关联复盘重新确认。
- 旧 DN 保留原正常品预占口径，不自动改写库存或历史流水。尚未完成的旧破损退供单需取消后按正确库存类型重建。
- 未关联的旧 `transfer` DN、`transfer/return_from_customer` ASN 不再允许继续发货或入库完成。取消并改用关联流程；已有分拣批次的 ASN 先按原流程撤销未过账批次，再取消。不要直接修改数据库数量或将退货单改成普通入库来绕过流程。
- 已入账历史记录不自动合成原销售单、检验结果或目标仓。升级前后应核对旧在途和旧退货实物。
- 降级会删除新增业务表，只适用于尚未使用新流程的回退或隔离测试，不能用于保留新业务数据的生产回退。
